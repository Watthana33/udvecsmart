ตอนที่ 1: ขั้นตอนการปฏิบัติ

ขั้นตอนการอัปโหลดไฟล์ขึ้น GitHub (เปิด 2 จอทำตามได้ทันที)

1

จอที่ 1 (เว็บเบราว์เซอร์): สร้าง Repository บน GitHub

1.1 เข้าเว็บ github.com แล้วล็อกอิน

1.2 กดปุ่มเครื่องหมายบวก `+` มุมขวาบน ➔ เลือก "New repository"

1.3 ตั้งชื่อโปรเจกต์ เช่น `udvecsmart`

1.4 เลือกสถานะเป็น 🔒 Private (ส่วนตัว) (สำคัญมาก เพื่อความปลอดภัยสูงสุด)

1.5 ไม่ต้องติ๊กถูก ช่อง Add README, .gitignore หรือ License เลย (เว้นว่างไว้ทั้งหมด)

1.6 กดปุ่มสีเขียว "Create repository" แล้วคัดลอกลิงก์ URL ที่ได้ เช่น: https://github.com/your-username/udvecsmart.git

2

จอที่ 2 (VS Code): พิมพ์คำสั่งใน Terminal ทีละบรรทัด

คำสั่งที่ 2.1: สั่งให้ Git กวาดไฟล์โค้ดทั้งหมด (ไฟล์ .env จะถูกข้ามให้อัตโนมัติอย่างปลอดภัย)
git add .
คำสั่งที่ 2.2: บันทึกเวอร์ชันแรก (Commit)
git commit -m "feat: complete UDPVECSmart version 1.0"
คำสั่งที่ 2.3: ตั้งชื่อกิ่งหลักเป็น main
git branch -M main
คำสั่งที่ 2.4: เชื่อมต่อเครื่องของคุณ เข้ากับ URL ของ GitHub ที่เพิ่งสร้างมา
git remote add origin https://github.com/ชื่อผู้ใช้ของคุณ/udvecsmart.git
คำสั่งที่ 2.5: ส่งข้อมูลทั้งหมดขึ้นสู่ GitHub
git push -u origin main
3

เชิญแอดมินเซิร์ฟเวอร์เข้าร่วมโปรเจกต์ (Collaborator)

3.1 ในหน้า GitHub ของโปรเจกต์ ให้ไปที่เมนู Settings ด้านบน

3.2 แถบซ้ายเลือก Collaborators ➔ กดปุ่ม "Add people"

3.3 พิมพ์ค้นหา Username หรือ อีเมล GitHub ของแอดมิน แล้วกดเชิญ

3.4 เมื่อแอดมินกดตอบรับ แอดมินจะสามารถใช้คำสั่ง git clone เพื่อดึงโค้ดไปรันบนเซิร์ฟเวอร์ได้ทันที

ตอนที่ 2: ไขข้อข้องใจเรื่องรหัสผ่าน & seed.ts

ลบไฟล์ `seed.ts` หลัง Build ได้ไหม? ระบบมาตรฐานเขาทำอย่างไร?

❓ ข้อที่ 1: หลังจากแอดมิน Build ขึ้นออนไลน์แล้ว ผมลบไฟล์ seed.ts ได้ไหม? จะมีผลกับระบบไหม?

คำตอบ: "ลบได้ และระบบบนเซิร์ฟเวอร์จะยังคงทำงานได้ตามปกติ 100% ครับ!"

เหตุผล: ไฟล์ seed.ts มีหน้าที่เพียงอย่างเดียวคือเป็น "รถส่งของรอบแรก" เมื่อแอดมินสั่งคำสั่ง npm run db:seed ข้อมูลจะถูกเทลงไปบันทึกถาวรในฐานข้อมูล PostgreSQL เรียบร้อยแล้ว หลังจากนั้นตัวเซิร์ฟเวอร์จริงจะทำงานผ่าน dist/server.js ซึ่งไม่เคยเปิดอ่านไฟล์ seed.ts อีกเลย แม้คุณจะลบไฟล์นี้ออกไป ฐานข้อมูลและเว็บไซต์ก็ไม่พังแน่นอนครับ

❓ ข้อที่ 2: ถ้าผมลบไฟล์ seed.ts ในเครื่อง แล้วตอนแอดมินอัปโค้ดไป ไฟล์นี้จะยังอยู่บนเซิร์ฟเวอร์ไหม?

คำตอบ:

  • ถ้าคุณลบในเครื่อง ➔ แล้วสั่ง git push ➔ เมื่อแอดมินสั่ง git pull ไฟล์ seed.ts บนโฟลเดอร์เซิร์ฟเวอร์ก็จะถูกลบตามไปด้วยครับ
  • แต่ ข้อมูลในฐานข้อมูลที่รันอยู่ข้างใน Docker จะ ไม่หายเด็ดขาด ครับ เพราะฐานข้อมูลเก็บอยู่ใน Docker Volume แยกต่างหากจากไฟล์โค้ด

🏆 ข้อที่ 3: ในระบบมาตรฐานสากล (Industry Standard) เขาจัดการเรื่องรหัสผ่านอย่างไรให้ถูกต้อง?

1. กฎทอง: ไม่ฮาร์ดโค้ดรหัสผ่านลงในไฟล์

ในระบบมาตรฐานสากล ไฟล์โค้ดจะไม่เขียนรหัสผ่านตรงๆ ลงไป แต่จะดึงค่าจากไฟล์ `.env` เช่น:
const pwd = process.env.INITIAL_ADMIN_PASSWORD; ซึ่งไฟล์ `.env` จะถูกตั้งค่าให้อยู่เฉพาะบนเครื่องเซิร์ฟเวอร์ปลายทาง ไม่เคยถูกอัปขึ้น Git เลย คนที่ดูใน Git จึงไม่มีทางรู้รหัสผ่าน

2. บังคับเปลี่ยนรหัสผ่านทันทีที่ระบบออนไลน์

ต่อให้ในไฟล์ seed.ts จะมีรหัสผ่านเริ่มต้นแบบชั่วคราวติดไป (เช่น ตอนตั้งต้นระบบ) เมื่อแอดมินเปิดระบบออนไลน์เสร็จ:
👉 คุณแค่ล็อกอินเข้าไปที่หน้าเว็บ แล้วกดปุ่ม "เปลี่ยนรหัสผ่าน" ทันที รหัสผ่านที่เคยอยู่ในโค้ดก็จะใช้ไม่ได้อีกต่อไปตลอดกาล

สรุปการแบ่งหน้าที่: สิ่งที่อยู่ใน Git vs สิ่งที่อยู่ใน Server

รายการ อยู่ใน GitHub ไหม? ใครเข้าถึงได้บ้าง?
ไฟล์โค้ด (.tsx, .ts, Dockerfile) ✅ อยู่บน GitHub เฉพาะคุณ และแอดมินที่ถูกเชิญ (Private)
ไฟล์รหัสผ่านจริง (.env) ❌ ไม่อยู่บน GitHub เด็ดขาด อยู่เฉพาะในเครื่องของคุณ และบนเครื่องเซิร์ฟเวอร์
ข้อมูลสถิติ & ประวัติผู้ใช้จริง ❌ ไม่อยู่บน GitHub อยู่ในฐานข้อมูล PostgreSQL ภายในเซิร์ฟเวอร์เท่านั้น
